# TOML 1.1 Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add full TOML 1.1 support (multi-line inline tables, trailing commas in inline tables, `\xHH`/`\e` escapes, optional seconds) with a default-1.1 parser and an opt-in strict-1.0 mode, built on the `william` TOML lexer, preserving all round-trip guarantees.

**Architecture:** Replace tomlet's line-based parser front-end with a token-driven pipeline: `william.tokenise` produces a trivia-preserving token stream; a new `tomlet/lexer` wrapper annotates each token with a byte offset; a rewritten `tomlet/parser` consumes those spanned tokens to build the existing `ast.Table`, enforce TOML rules, and gate features by version. The public `tomlet` API gains an additive `Options`/`parse_with` surface.

**Tech Stack:** Gleam (Erlang + JavaScript targets), `william` (TOML lexer), `gleeunit`, `just`, Changie, Python corpus harness (`scripts/run_corpus_tests.py`), `toml-lang/toml-test` fixtures.

**Spec:** `docs/superpowers/specs/2026-06-17-toml-1.1-support-design.md`

- [ ] **Step 3: Implement the lexer wrapper**

`william.to_source` reconstructs a token's exact text via an internal `token_source`; reuse it by re-tokenising is unnecessary — wrap each token's source through `william.to_source([token])`, whose byte length is the token's span. Accumulate byte lengths to assign offsets.

```gleam
//// Internal module -- not part of Tomlet's public API.
////
//// Wraps the `william` TOML lexer and annotates every token with the byte
//// offset at which it begins, so the parser can report byte-accurate errors.

import gleam/list
import gleam/string
import william.{type Token}

pub type Spanned {
  Spanned(token: Token, offset: Int)
}

/// Tokenise TOML source into spanned tokens carrying byte offsets.
pub fn lex(input: String) -> List(Spanned) {
  let tokens = william.tokenise(william.new(), input)
  annotate(tokens, 0, [])
}

fn annotate(tokens: List(Token), offset: Int, acc: List(Spanned)) -> List(Spanned) {
  case tokens {
    [] -> list.reverse(acc)
    [token, ..rest] -> {
      let width = string.byte_size(william.to_source([token]))
      annotate(rest, offset + width, [Spanned(token: token, offset: offset), ..acc])
    }
  }
}
```

>
> ```gleam
> pub type Version {
>   Toml10
>   Toml11
> }
>
> pub fn parse(input: String, version: Version) -> Result(ast.Table, ParseError) {
>   assemble(lexer.lex(input), version)
> }
> ```
>
> `assemble` is the new recursive-descent parser over `List(lexer.Spanned)`. It returns `Result(ast.Table, ParseError)`, producing the exact same `ast.Table`/`Entry`/`Value` shapes (`src/tomlet/ast.gleam`) the editing and round-trip code already consumes. Errors use the existing `parser.Unexpected`/`parser.KeyAlreadyInUse` variants with the spanned token's `offset`.
>
> Each task below specifies the construct, a representative failing test, and the assembly responsibilities. Implement the minimal assembly code to pass each test and its corpus subset before moving on.

For every task in this group, the loop is:
1. Add the unit test shown (real assertions on `parser.parse(input, parser.Toml11)` via a thin test that compares `tomlet.to_string`/`tomlet.get` round-trips, or directly on `ast.Table` where noted).
2. Run it, confirm it fails.
3. Extend `assemble` to handle the construct.
4. Re-run the unit test and the named corpus subset; confirm PASS.
5. Commit with a `feat(parser): assemble <construct>` message.

The corpus subset for a task is obtained by temporarily routing `tomlet.parse` through the new `parser.parse(_, Toml11)` (done once in Task 1.10's precursor — see note) **or** by writing the unit test directly against `parser.parse`. To keep tasks independent, write unit tests directly against `parser.parse` in this group; the full corpus switch-over happens in Task 1.10.
