# TOML 1.1 Support — Design

Date: 2026-06-17
Status: Approved (brainstorming complete; implementation plan pending)

## Summary

Add full TOML 1.1 support to tomlet by replacing the current line-based parser
core with a token-driven pipeline built on the [`william`](https://hex.pm/packages/william)
TOML lexer. TOML 1.1 is accepted by default; an opt-in strict TOML 1.0 mode
rejects 1.1-only syntax. All existing round-trip guarantees are preserved.

## Goals & Scope

Implement all TOML 1.1 features:

1. **Multi-line inline tables** — newlines and indentation allowed inside `{ ... }`.
2. **Trailing commas** in inline tables (arrays already permit them in 1.0).
3. **New basic-string escapes** — `\xHH` (two-digit hex, codepoint ≤ 255) and
   `\e` (ASCII escape character).
4. **Optional seconds** in time and datetime values (e.g. `13:15`,
   `2010-02-03T14:15`).

Out of scope: any speculative TOML 1.2 features; highlighting/rendering use of
william (only its lexer is used).

## Constraints (must hold)

- Default parsing accepts TOML 1.1. A strict TOML 1.0 mode **rejects** 1.1-only
  syntax.
- Round-trip behavior is preserved: unedited parsed documents return their
  original source byte-for-byte; edits preserve nearby comments, key order,
  trivia, and CRLF/LF line-ending style.
- Public API in `src/tomlet.gleam` remains semver-stable. Existing functions and
  variant types are unchanged; only additive API is introduced.
- Internal modules (`tomlet/ast`, `tomlet/parser`, `tomlet/path`, `tomlet/key`)
  remain implementation details.
- Both Erlang and JavaScript targets must pass.

## Architecture

Replace the line-based core (`string.split(input, "\n")` + `merge_multiline_lines`
+ per-line parsing) with a token-driven pipeline:

```
source
  ──william.tokenise──▶  [william.Token]        (raw, trivia-preserving, recoverable)
  ──tomlet validator──▶  ast.Table + trivia      (rejects invalid TOML, gates version)
```

### Lexing (william)

`william.tokenise` produces a `List(Token)` where each token preserves its raw
source text:

- Trivia tokens: `EndOfLine(str)` (preserves `\r\n` / `\n` / `\r`),
  `Whitespace(str)`, `Comment(str)`.
- Value/key tokens carry raw text: `BareKey(name)`,
  `String(delimiter, value)`, `Boolean`, `Integer(base, value)`, `Float`,
  `DateTime(value)`.
- Structural tokens: `Equal`, `Dot`, `Comma`, `OpenTable`/`CloseTable`,
  `OpenArrayTable`/`CloseArrayTable`, `OpenBracket`/`CloseBracket`,
  `OpenBrace`/`CloseBrace`.
- Error tokens: `Unexpected`, `InvalidNumber`, `UnterminatedString`.

william models inline-table/array **containers** internally and emits
`EndOfLine` tokens inside them, so multi-line inline tables and trailing commas
are handled at the lexing layer with no special-casing in tomlet. `william.to_source`
reconstructs source exactly from tokens, confirming the token stream is
lossless.

Dependency: depend on `william` as published, accepting its transitive
dependencies (`splitter`, `gleam_community_ansi`, `houdini`). Only the lexer
(`william.new`, `william.tokenise`, `william.Token`) is used; highlight/ANSI/HTML
functions are ignored.

### Validation / parse layer (new, tomlet-owned)

A new tomlet-owned layer consumes `[william.Token]` and:

- Builds the existing trivia-preserving `ast.Table` (and value source
  preservation) so downstream editing/round-trip code is unchanged.
- Enforces TOML rules that william does not: duplicate-key detection,
  structural validity (table/array-of-tables nesting, dotted-key resolution via
  `tomlet/path`), and value well-formedness (numbers, dates/times, string
  escapes).
- **Reconstructs byte offsets.** william tokens carry no position information;
  the layer accumulates `token_source(token)` byte lengths to compute the byte
  offset of each token, so `parser.ParseError` offsets remain accurate and
  `tomlet.line_column` keeps working.

### Error model

william is recoverable: it emits `Unexpected` / `InvalidNumber` /
`UnterminatedString` tokens and never fails. tomlet's validation layer converts
those error tokens — plus its own rule violations — into the existing
`parser.ParseError` variants (`Unexpected`, `KeyAlreadyInUse`) with byte
offsets, which `src/tomlet.gleam` maps to stable public `ParseError` variants.
Public error variants are unchanged.

## Version Gating & Public API (additive)

- New public `TomlVersion` enum with variants `Toml10` and `Toml11`.
- New opaque `Options` type with:
  - `default_options() -> Options` (defaults to `Toml11`).
  - `with_version(Options, TomlVersion) -> Options` builder.
- New `parse_with(input: String, options: Options) -> Result(Document, ParseError)`.
- New `parse_bytes_with(input: BitArray, options: Options) -> Result(Document, ParseError)`.
- Existing `parse` / `parse_bytes` are retained and default to `Toml11`.

Strict mode (`Toml10`) rejects, in the validation layer keyed off the selected
version:

- Newlines (`EndOfLine`) or a trailing comma inside inline tables.
- `\xHH` and `\e` escapes in basic strings.
- Times/datetimes lacking a seconds component.

These rejections surface as `ParseError` with the offending byte offset.

## De-risking Spike (Phase 0 — gates the rest)

Before committing to the rewrite, prove william is sufficient:

1. Tokenise the entire `toml-test` corpus (valid + invalid) and assert
   `william.to_source(tokens) == source` byte-for-byte for every fixture.
2. Confirm william tokenises the four 1.1 constructs without losing raw text
   (opaque handling is acceptable as long as the raw text survives for the
   validator to interpret).
3. Confirm byte offsets reconstructed from token lengths match expected
   positions on a sample of fixtures (including CRLF and multibyte-UTF-8 cases).

If any check fails irreparably, fall back to **Approach C**: a tomlet-owned
tokenizer that borrows william's design. Spike findings are recorded in the
implementation plan before proceeding.

### Spike findings (2026-06-17, GO)

william 1.0.1 round-trips **735 of 735** UTF-8-readable corpus fixtures exactly
(`william.to_source(william.tokenise(source)) == source`), with 0 failures. The
11 skipped fixtures are the invalid-UTF-8 byte cases under `invalid/encoding/*`,
which tomlet already rejects at the byte layer (`parse_bytes`) before lexing, so
william never sees them as `String`. All four TOML 1.1 constructs (multi-line
inline table, `\x41`/`\e` escapes, second-less time, second-less datetime)
round-trip exactly. Erlang and JavaScript targets agree (184 tests each).
Proceeding with **Approach A**.

## Testing & Definition of Done

- Extend `scripts/run_corpus_tests.py` to run **both** the TOML 1.0 and TOML 1.1
  fixture sets from `toml-lang/toml-test`, on both Erlang and JavaScript targets.
- Default (1.1) parsing passes the 1.1 valid/invalid suites.
- Strict (1.0) parsing passes the 1.0 suites and **rejects** 1.1-only valid
  fixtures.
- Round-trip-exact remains required for valid fixtures, honoring the existing
  `ROUNDTRIP_UNSUPPORTED` allowlist.
- Gleam unit tests added for each 1.1 feature and for strict-mode rejection,
  passing on both targets.
- `just ci` is green (format, lint, test, build, docs).
- A Changie `Added` fragment is included under `.changes/unreleased/`.

## Rollout (phased, each independently testable)

0. **Spike** — validate william against the corpus and 1.1 constructs.
1. **Token-driven parser parity** — replace the line-based core with the
   william-based validation layer; reach parity on the existing TOML 1.0 corpus
   and all current unit tests. No behavior change yet.
2. **1.1 features + strict gating** — add multi-line inline tables, trailing
   commas, new escapes, and optional seconds; add version gating so `Toml10`
   rejects 1.1-only syntax.
3. **Public API + docs** — add `TomlVersion`, `Options`, `parse_with`,
   `parse_bytes_with`; update README/DEV docs and the `links` TOML-spec
   reference; add the Changie fragment.

## Risks

- **Single-author dependency on the critical path.** Mitigated by the spike and a
  documented fallback to a tomlet-owned tokenizer.
- **william 1.1 fidelity.** It may treat new escapes/optional-seconds opaquely;
  acceptable as long as raw text survives. Verified in the spike.
- **Offset reconstruction accuracy** across CRLF and multibyte UTF-8. Covered by
  spike check 3 and unit tests.
- **Transitive dependency weight** (`ansi`, `houdini`) added to all tomlet
  consumers. Accepted for now; revisitable by vendoring the lexer later.
